# 01 · 方案落地（Delivery Plan）

> 把 [00-教学方案](./00-教学方案.md) 排进现实日程：环境准备、每课活动、里程碑、Capstone 细节、节奏建议。

## 1. 实验环境准备（开课前一次性做完）

| 项 | 要求 | Windows 提示 🪟 |
|----|------|----------------|
| Go | 1.25+（`go version` 验证） | go.dev/dl 装 |
| Git | 任意新版 | 你已有 `D:\Git` |
| 仓库 | clone 本仓库 | 已在本地 |
| 构建 | `go build -o bin/skill-up.exe ./cmd/skill-up` | 能产出 exe 即 OK |
| Agent CLI（可选） | 装真实 Agent 才能跑完整评测 | 完整跑 Agent 需 WSL2；只体验用例/规则评分可原生 |
| API Key（可选） | ANTHROPIC/OPENAI/QODER 任一 | 有预算再配；L02/L04 的 rule/script 练习不需要 |
| AI Agent（可选） | Claude Code / Codex 装 skill-upper 用 | 对话式闭环用 |

> **最小可学配置**：Go + 仓库 + 构建 exe。靠 `validate` / `list-cases` / rule_based 用例就能学完 L01–L04 大部分。

## 2. 每课教学活动（标准化）

每课 ≈ 「**讲 30% + 练 50% + 测 20%**」：

```
① 讲解（读文档，跟 Java 类比）          ~30 min
② 动手练习（照着做，必做）                ~40-60 min
③ 检查点自测（合上文档答）                ~15 min
④（可选）深入阅读 dev-doc/deep           按精力
```

## 3. 课程进度表（标准 1 周节奏）

| 天 | 课 | 课外 | 里程碑 |
|----|----|------|--------|
| D1 | L01 + L02 | 跑通 examples/code-stats 的 validate | ★ 跑通第一次评测 |
| D2 | L03 | 画出 executeCaseOnce 7 步图 | ★ 能讲端到端流程 |
| D3 | L04 | 写 rule_based + script 两种 judge | ★ 能选 judge 策略 |
| D4 | L05 + L06 | 画「加新引擎」改动点；对比 parallelism | ★ 懂引擎+并发 |
| D5 | L07 | 跑一次 with/without benchmark | ★ 懂报告+安全 |
| D6–D7 | L08 | 写简历段 + 模拟面试 + 启动 Capstone | ★★ 毕业 |

> **周末速成版（2 天）**：D1 = L01+L02+L03，D2 = L08 面试部分 + 简历。Capstone 略。
> **深入版（2 周）**：每天 1 课 + 把该课 `dev-doc/deep` 全看完 + D8–D14 做 Capstone。

## 4. 关键里程碑（自检门）

每个里程碑过了再往下走，没过回去补：

- **M1 跑通**（L02 后）：能 `validate` + `run` 一个现成用例，看懂 PASS/FAIL。
- **M2 讲流程**（L03 后）：不看文档，白纸画出单 case 7 步 + 标注 expect 短路、judge.Input 边界。
- **M3 会选型**（L04–L06 后）：给一个场景，能说出用哪种 judge / 哪种 runtime / 并发多少。
- **M4 能输出**（L07 后）：能讲清 grading/benchmark 区别、A/B 的 delta 怎么来的、安全防了什么。
- **M5 毕业**（L08 后）：30 秒演讲 + 10 题答 8+ + Capstone 完成。

## 5. Capstone 实战项目（毕业交付）

> 详细在 [L08](./L08-面试与实战.md)，这里给总览 + 评估。

**目标**：从 0 做一个**小 Skill + 完整评测套件**，作为简历可演示产出 + 真实技能验证。

**建议选题**（挑一个，别贪大）：
- 「commit message 规范检查」Skill（检测是否符合 conventional commits）
- 「代码格式自检」Skill（对diff 做基础检查）
- 你自己工作里有的一个小需求

**交付清单**：
1. `SKILL.md`（技能定义）
2. `evals/eval.yaml` + `cases/*.yaml`（5–8 个用例，含正例/反例/边界）
3. 至少 2 种 judge（rule_based + script，有预算再加 agent_judge）
4. 跑一次 `benchmark.enabled=true`（with/without skill 对比）
5. （加分）用 skill-upper 迭代修复一轮
6. 一页 `README` 说明：Skill 干啥、评测覆盖了啥、benchmark 结果说明了啥

**评估 Rubric**（10 分制，≥7 算过）：
- 用例覆盖度（正/反/边界）（3 分）
- judge 选型合理性（2 分）
- benchmark 解读（2 分）
- 文档可读性（2 分）
- 迭代深度（加分 1 分）

**时间预估**：4–8 小时。别追求完美，**跑通+能讲** > 精雕细琢。

## 6. 学习节奏建议

- **每天固定 1.5–2 h** > 周末突击 10 h（细水长流记得牢）
- **「讲」是终极检验**：每课学完试着对我（或橡皮鸭）讲一遍，讲不清就是没懂
- **卡住了别硬磕**：标记下来，往下走，后面会串起来（很多概念 L03 之后才通透）
- **代码别只读**：`dev-doc/deep` 里的代码片段，去源码里点开看上下文
