# 00 · 教学方案（Syllabus）

> 这是课程的设计蓝图：目标、受众、理念、结构、考核。落地计划见 [01-方案落地.md](./01-方案落地.md)。

## 1. 课程定位

**「skill-up 精修课」**：把一个 Alibaba 开源的 Go 项目（Agent Skill 评测框架），在 1–2 周内，带一位 Java 工程师达到「**能在面试讲透、能在简历写好、能在实战用上**」的水平。

不是泛泛读完文档，而是**定向攻克简历+面试**，并产出一份可演示的 Capstone。

## 2. 受众画像

- **角色**：Java 后端 / 全栈工程师
- **目标**：改简历、过技术面、（可选）真实用 skill-up 评测自己的 Agent Skill
- **知识基线**：
  - 熟悉 Spring/Java 生态（讲解全程用 Java 类比）
  - 了解 LLM / AI Agent / Claude Code / Codex（不了解 L01 会补）
  - 会基本命令行（clone/build）
  - 多数在 Windows 上（课程全程标注 🪟）
- **常见障碍**：Go 语法不熟、对「Agent Skill」概念陌生、怕面试被追问到源码细节

## 3. 教学目标（学完能做到）

按 Bloom 分类，从低到高：

| 层级 | 目标 | 对应课 |
|------|------|--------|
| **理解** | 用自己的话讲清 skill-up 是什么、解决什么痛点、声明式含义 | L01 |
| **应用** | 独立安装、写 YAML 用例、跑通评测、读懂报告 | L02 |
| **分析** | 画出端到端时序、拆解单 case 7 步、识别三条数据契约 | L03 |
| **分析** | 对比三种 Judge 策略、四种 Agent 引擎、三种 Runtime 后端，能选型 | L04–L06 |
| **评价** | 评判设计取舍（为什么这么抽象、为什么这么容错、为什么这么防御） | L04–L07 |
| **创造** | 独立设计一个 Skill + 完整评测套件（Capstone） | L08 |

**毕业硬指标**（做不到就回去补）：
1. 30 秒电梯演讲讲清项目 ✅
2. 白板画出架构 + 单 case 流程 ✅
3. 答出 [L08](./L08-面试与实战.md) 的 10 道高频题（≥8 道自评 4/5）✅
4. 完成 Capstone 并自评达标 ✅

## 4. 教学理念

1. **先用后懂**：L02 先跑通建立体感，再回头讲原理（L03+）。避免一上来灌架构图。
2. **Java 类比贯穿**：每个 Go 概念都桥接到你熟的 Java/Spring 世界（goroutine≈轻线程、Cobra≈Picocli、OTel≈SkyWalking、interface 组合≈Spring JDBC…）。
3. **「为什么」>「是什么」**：不只讲做了什么，更讲设计取舍（为什么 expect 要短路、为什么 judge.Input 是边界、为什么 CustomAgent 不嵌 CLIAgent）—— 这是面试区分度。
4. **动手为王**：每课有必做练习；不做≈没学。
5. **分层留口**：每课「深入阅读」指向 `dev-doc/deep/` 源码，按精力选深浅。

## 5. 课程结构（8 课）

| 模块 | 课 | 类型 | 核心问题 |
|------|----|------|---------|
| **入门** | L01 建立认知 | 概念 | 它是啥？不是啥？ |
| | L02 动手跑通 | 实操 | 怎么用？ |
| **主线** | L03 核心流程 | 架构 | 一次 run 怎么转完？ |
| **深挖** | L04 评测打分 | 子系统 | 怎么打分？ |
| | L05 引擎适配与配置 | 子系统 | 怎么接各种 Agent？ |
| | L06 跑得稳 | 基础设施 | 怎么不出错？ |
| | L07 输出与安全 | 产出+护栏 | 怎么出报告+防坑？ |
| **转化** | L08 面试与实战 | 毕业 | 怎么写简历+答面试+做项目？ |

**节奏设计**：L01–L03 是「会+懂主线」必读；L04–L07 平行展开讲深度（按面试兴趣选序）；L08 收口转化。

## 6. 考核标准（Rubric）

每项 1–5 分，毕业要求总分 ≥ 32/40 且无单项 ≤ 2：

| 维度 | 1（弱） | 3（合格） | 5（优秀） |
|------|--------|----------|----------|
| **概念清晰度** | 讲不清定位 | 能讲清是什么 | 能讲清+区分易混概念 |
| **使用能力** | 没跑通 | 能跑+读懂报告 | 能写复杂用例+调优 |
| **架构理解** | 背不出流程 | 能画 7 步流程 | 能讲三条数据契约+取舍 |
| **深度** | 只会说名词 | 能讲 1 个子系统 | 能下钻源码细节 |
| **简历/面试** | 写不出 | 有描述但泛 | STAR+亮点+诚实定位 |
| **实战 Capstone** | 没做 | 跑通基础 | 三种 judge+A/B+迭代 |
| **表达** | 磕巴 | 30 秒能讲 | 能应对追问 |
| **诚实度** | 夸大 | — | 正确归属 Alibaba 开源 |

> 第 8 项「诚实度」是**一票否决**：这是 Alibaba 开源项目，简历必须如实写「学习/参与/基于它二次开发」，谎称独立开发 = 诚信问题。
