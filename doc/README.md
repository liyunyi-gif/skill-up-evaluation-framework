# skill-up 项目技术梳理（简历向）

> 本目录是为「理解项目 + 改简历」准备的技术梳理，独立于官方 `docs/`（那是 VitePress 用户手册）。
> 面向读者：Java 后端 / 全栈工程师，需要把这个 Go 项目写进简历并能在面试中讲清楚。

## 这是什么项目

**skill-up** 是 Alibaba 开源的 **Agent Skill 评测与演进 CLI 框架**（Go 1.25）。

一句话定位：**「给 AI Agent 的 Skill 写单元测试 / 回归测试」**。
你声明 YAML 用例 → 框架把 Skill 装进真实 Agent 引擎（Claude Code / Codex / Qoder CLI / 通义千问 qwen_code）→ 跑 prompt → 用「规则 / 脚本 / LLM 裁判」打分 → 产出结构化报告，并支持跨引擎对比、with/without Skill 基线 A/B、CI 集成、OpenTelemetry 全链路追踪。

它解决的痛点：Agent Skill（给 AI Agent 用的「技能包/插件」）的质量过去只能靠人肉试，没有可度量、可复现、可回归的工程化手段。skill-up 把这件事产品化成一个 CLI。

## 核心定位：skill-up 不是什么（防混淆 ⚠️）

最容易搞错的一句：**skill-up 不拓展 Coding Agent 的能力边界，它只「验证」Skill 的能力是否达标。**
拓展 agent 能力的是 **Skill 本身**，skill-up 是站在 Skill 下游的**质检层**。

### 层级关系图

```
┌──────────────────────────────────────────────────────┐
│  Coding Agent  (Claude Code / Codex / Qoder CLI …)   │  ← 你日常用的 AI 编程助手
│  ┌────────────────────────────────────────────────┐  │
│  │  Skill  (技能包 / SKILL.md)                     │  │  ← ★ 拓展 agent 能力边界的是它
│  │     = 给 agent 装的「App」                       │  │     (让 agent 会做原本不会的事)
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
                         ▲
                         │ skill-up 把 Skill 临时装进 agent（在隔离沙箱里、跑完即删）
                         │ → 这是「测试夹具」，不是「能力升级」
                         │
┌──────────────────────────────────────────────────────┐
│  skill-up  (评测框架 / CLI)                           │  ← ★ 这一层不增加能力，只验证能力
│     = Skill 的「质检流水线 / 考试系统」               │     跑用例 → 打分 → 出报告
└──────────────────────────────────────────────────────┘
```

### 方向图：谁调用谁（别搞反 ⚠️）

`skill-up` 和 `skill-upper` 名字像、方向**相反**，是最容易绕的点。看箭头方向：

**关系① — skill-up（司机 → 车）**
```
   skill-up  ────启动/调用(当子进程)────▶  Claude Code / Codex
  (独立 Go 程序)                           (被测对象 / 工具)
        ▲                                     │
        └────────返回输出 / transcript─────────┘
   ★ skill-up 是主，它把 cc 当工具跑（不是被 cc 装进去）
```

**关系② — skill-upper（宿主 → 插件）**
```
   Claude Code / Codex  ────装载────▶  skill-upper
   (宿主)                              (一个 Skill / 车载 App)
                                          ▲
                          借用 cc 的模型能力，生成/迭代测试用例
   ★ cc 是主，skill-upper 是它的插件（被 cc 装进去）
```

**哪件事归谁**
| 你想干的 | 归谁 | 怎么干 |
|---|---|---|
| 生成测试用例 | **skill-upper**（关系②） | 在 cc 里、用 cc 的模型读 SKILL.md 写 YAML |
| 跑测评流程 | **skill-up**（关系①） | 自己的 Go 代码编排，**启动 cc 当被测对象** |
| 打分（rule/script） | **skill-up** 自己 | 纯代码，不需要模型 |
| 打分（agent_judge） | **skill-up** 起裁判 agent | 这一步才调模型 |

> 一句话：**skill-up 是「司机」，cc/codex 是它开的「车」，skill-upper 是「车载 App」。** 司机不是被车装的，是司机在开车 —— 所以 skill-up 和 cc 关系不是「没有」，是「它在驱动 cc」。

### 谁干啥（一张表分清）

| | 是谁 | 干啥 | 拓展 agent 能力？ |
|---|---|---|---|
| **Skill** | 给 agent 用的能力模块 | 让 agent 学会新本事 | ✅ 是它拓展 |
| **skill-up** | Skill 的考试系统 | 跑用例、打分、出报告 | ❌ 只验证，不增加 |
| **skill-upper** | 仓库附带的一个 Skill | 让 agent 自动写测试用例 | ✅（因为它是 Skill） |

> 类比：**skill-up 之于 Skill ≈ JUnit 之于 Java 代码 ≈ CI 之于代码** —— 都不让你代码「更强」，只让你知道「它没坏」。
>
> 面试正确口径：**「Agent Skill 的评测与质量保障框架」**，别说成「拓展 agent 能力的平台」—— 差一个层级。

## 技术栈速览（Go 相关）

| 类别 | 技术 |
|------|------|
| 语言/版本 | Go 1.25（用到 `maps`、`slices`、`min/max` 等新特性） |
| CLI 框架 | `spf13/cobra` + `spf13/pflag` |
| 配置 | `gopkg.in/yaml.v3`，自研 `v1alpha1` schema + 分层校验器 |
| 可观测性 | OpenTelemetry（OTLP gRPC/HTTP，trace + metric），`go.opentelemetry.io/otel` 全家桶 |
| 沙箱后端 | 自研 `internal/runtime`：none / OpenSandbox（Alibaba 远程沙箱 SDK）/ Docker（shell out） |
| 文件匹配 | `bmatcuk/doublestar`（globs） |
| 依赖注入 | 不用框架，**构造器注入 + 接口**（Go 惯例） |
| 测试 | 表驱动测试为主，`go test -race`，e2e 用 build tag 隔离 |
| 构建/发布 | GoReleaser + GitHub Actions，`-ldflags` 注入版本号 |
