# 03 · 三大子系统详解

> 本篇是「字典」—— 被追问时下钻用。基于源码 + 三轮代码深挖整理。
> 三大子系统：**① Judge 评分** **② Agent 引擎适配** **③ Runtime 隔离 + Report 生成**。

---

## 子系统 ① Judge 评分系统（`internal/judge/`）

### 整体位置
每个 case 执行完后，评分分两步：`expect 预检查 → Judge.Evaluate`，失败短路；通过后 expect 断言前置拼到 judge 断言一起算分。

### 三种策略对比

| 维度 | rule_based | script | agent_judge |
|------|-----------|--------|-------------|
| 文件 | [rule_based.go](../internal/judge/rule_based.go) | [script.go](../internal/judge/script.go) + [interpreter.go](../internal/judge/interpreter.go) | [agent_judge.go](../internal/judge/agent_judge.go) + [context_materializer.go](../internal/judge/context_materializer.go) |
| 确定性 | 完全确定（纯 Go） | 确定（退出码） | 非确定（LLM） |
| 成本 | 零 | 低（跑脚本） | 高（一次 LLM 调用） |
| PASS 判定 | failure 全不命中 + success 全过 | exit code == 0 | pass_rate ≥ pass_threshold(默认 0.7) |
| 适用 | 关键字/工具调用/文件产出 | 复杂逻辑判定/跑测试套件 | 开放式语义评测（代码质量、bug 定位） |

### rule_based 实现要点
- **评估优先级**（[rule_based.go:33-67](../internal/judge/rule_based.go#L33)）：**先评 failure 规则**（任一命中立即 FAIL 短路），**再评 success**（全过才 PASS），都没配默认 PASS。
- **failure 语义反转**：一条 failure 规则 `Passed==true` 表示「坏模式被找到了」→ 整体 FAIL。用 `"failure: " + ar.Text` 前缀标注。
- **断言类型**：`output_contains`(all/any/not) / `exit_code` / `tool_called`(支持 args 部分匹配) / `files_exist` / `turn_response_contains`（多轮按 turn 号定位）/ `tool_called_in_turn`。
- **多轮定位**（`lookupTurn`）：区分「turn 不存在」和「turn 存在但状态非 completed」两种失败，evidence 细到便于排查。

### script 实现要点（跨平台脚本派发是精华）
- **契约**：cwd = workspace 根目录；env 传参 `EVAL_TRANSCRIPT_PATH`/`EVAL_FINAL_MESSAGE`/`EVAL_EXIT_CODE`；退出码 0=PASS 非 0=FAIL；stdout=evidence。
- **统一 runtime**：无注入 runtime 时建临时 `none` runtime，让本地/容器/远程走同一代码路径。
- **`planScript` 跨平台分流**（[interpreter.go](../internal/judge/interpreter.go)）：
  - POSIX：`chmod 700 <q> && <q>`，交给 shebang；
  - Windows：按扩展名 + shebang 双判定 → `.ps1`(pwsh/powershell 选) / `.cmd`(`cmd /c`) / `.sh`(必须 bash，路径转正斜杠让 Git Bash 的 `cat` 能读)。
- **shebang 解析器**：实现了 `/usr/bin/env` + GNU `env -S` split-string（含一个处理引号/转义的小型 tokenizer 状态机）。
- **清理用 `context.WithoutCancel`**：父 ctx 取消后仍能 `rm -rf` 清理临时目录。

### agent_judge 实现要点（LLM 裁判）
- **流程**：物化上下文 → 构造 prompt（角色约束 + 强制 JSON + criteria 列表 + 材料表 + 响应模板）→ 单条 user message 调 `Agent.Run` → `extractJSON` 四层兜底解析 → 校验（结果数==criteria 数 + evidence 非空）→ 阈值判定。
- **容错** `canRecoverAgentJudgeResult`：即使 Agent 调用报错，只要 FinalMessage 非空且非取消，仍尝试解析输出。
- **错误包裹** `SessionResultError`：失败时保留裁判 session，调用方仍能下载裁判 run 的 artifacts。

### context_materializer（为什么需要）
被测产出在「执行层 runtime」，裁判是「独立 agent 会话」（自己的 runtime workspace），两者不共享文件系统。所以要把裁判需要看的材料**物化**：写 host 磁盘（可留存）→ `UploadFile` 到裁判 runtime。
- **Profile × Mode 双维控制** prompt 体积（见 [02-核心技术点.md](./02-核心技术点.md) B4）。
- 物化 5 类材料：final_message.txt / transcript.json(可截最近 N 轮) / workspace.diff(可截行) / generated_files.txt / attachments。
- 输出 `manifest.json` 记录每个材料交付决策。

### expect 预检查
- **纯函数**（除读文件外无副作用），返回 `ExpectResult{Passed, Failures}`。
- 规则：`must_contain`(全包含) / `must_not_contain` / `exit_code` / `files_exist`/`files_not_exist` / `golden_file`(全文比对+首差异偏移提示) / `file_contains`。
- **路径安全**：`safePath` 严格防 `../../etc/passwd` 穿越到 workspace/skillDir 之外。
- **断言生成**：通过和失败的规则都生成 AssertionResult（通过的 evidence="all checks passed"），保证报告能看到「expect 检查了什么」。

### 数据结构设计（[judge.go](../internal/judge/judge.go)）
- `Input`：执行层→评测层统一边界（见 02 A3）。
- `Result`：三态 `Status`(PASS/FAIL/**SKIP**/ERROR，SKIP/ERROR 分离让「跳过」和「评测挂了」可区分) + `AssertionResults[]`(Text/Passed/Evidence) + `Summary`(passed/failed/total/pass_rate)。
- `NewResult`：无断言时 pass_rate=1.0（vacuous pass）—— 显式定义边界语义。
- 工厂方法三件套：`NewResult`/`NewSkipResult`/`NewErrorResult`。

## 子系统 ② Agent 引擎适配层（`internal/agent/`）

### Agent 接口契约（7 方法 + 1 可选）
[agent.go:132-148](../internal/agent/agent.go#L132)：

| 方法 | 职责 |
|------|------|
| `Name()` | 引擎名 |
| `Install(ctx,rt)` | 装 Agent CLI（幂等，已存在 short-circuit） |
| `InstallMCP(ctx,rt,cfg)` | 注册 MCP server（`claude mcp add` 等） |
| `InstallSkill(ctx,rt,cfg)` | 把 skill 目录上传到引擎 skill 路径（`.claude/skills` 等） |
| `Run(ctx,rt,opts,messages)` | **核心**：执行一轮，返回 `SessionResult` |
| `Check(ctx,rt)` | 检查可执行文件在 PATH（`command -v claude`） |
| `CheckCredentials(ctx)` | 检查凭据（实际只 warn 不 fail，因为可能用本地登录态） |

可选 `SessionResumer.RunTurn(ctx,rt,opts,msg,sessionID)` —— 多轮续接。编译期断言：只有 Claude/QoderCLI/Codex 实现了它；QwenCode/Custom 暂未支持多轮。

### 四层组合（见 02 A2）
`BaseAgent → CLIAgent(模板方法) → 具体适配器`；CustomAgent 绕过 CLIAgent 直接嵌 BaseAgent（**组合优于继承，控制接口表面**）。

### 三大适配器差异速查

| 维度 | ClaudeCode | Codex | QoderCLI |
|------|-----------|-------|----------|
| 安装 | npm `@anthropic-ai/claude-code` | npm `@openai/codex` | 官方 install 脚本（自包含二进制，非 node） |
| SkillPath | `.claude/skills` | `.codex/skills` | `.qoder/skills` |
| 凭据 env | `ANTHROPIC_API_KEY`(+`AUTH_TOKEN` 双写) | `OPENAI_API_KEY` | `QODER_PERSONAL_ACCESS_TOKEN` |
| 输出格式 | 文本 `-p` + JSONL session | `--json` NDJSON 流 + session JSONL + last-msg 文件 | 文本 stdout + JSONL session |
| sessionID | 自生成 UUID | 从 `thread.started` 事件解析 | 从 session 文件路径提取 |
| 多轮 resume | `--resume <sid>` | `exec resume <sid>` | `-r <sid>` |
| 特殊 | OTel 遥感 env；401/403/429 信号识别 | **合成 `skill-up-openai` provider**（绕兼容代理坑） | 模型白名单(lite/efficient/auto/performance/ultimate) |

**几个亮点细节**：
- **Claude 双写 `ANTHROPIC_AUTH_TOKEN`**：有些代理只认 `Authorization: Bearer`，双写覆盖两种 flavor。
- **Codex 合成 provider**：自定义 base_url 时合成 `skill-up-openai` provider，`wire_api=chat` 强制走 `/chat/completions`（很多兼容代理不支持默认的 `/responses`）。
- **Codex MCP 桥接脚本**：codex `mcp add` 不支持带 headers 的 HTTP MCP，于是生成 `exec npx mcp-remote` 的 sh 脚本包装。

### Custom Engine（local + http 双传输）
- **设计目标**：让用户接入任何 Agent 服务不改源码。
- **`${var}` 自研模板**（非 Go `text/template`）：`${workspace}` `${prompt}` `${input_file}` `${output_file}` `${api_key}` `${case_id}` `${model}` `${kwargs.<k>}` + env 兜底；支持 `${name:-default}` `${name?error}`。
- **localTransport**：runtime 内 `Exec`；运行前 `clearStaleOutputFile`（防上次结果被误读，重复解析符号链接防 TOCTOU）；检测 API key 是否被渲染进命令行（`errSecretInCommand`）；即使 execErr 也读 output_file（捞部分结果）。
- **httpTransport**：只 POST；URL 不能含 key；`request_body` 里 `${session_input}`/`${messages}`/`${kwargs}` 作为 JSON 结构注入（`json.RawMessage`）；配 `http.files` 组 multipart（doublestar glob，256MB 上限）。
- **安全护栏**：见 02 B5。

### 辅助机制
- **prompt_delivery.go**：超长 prompt 双模式（见 02 B7）。
- **node_install.go**：nvm/node 引导（见 02 B7）。
- **session_lookup.go**：抽象「找 session JSONL 文件」流程，`withDownloadedSession` 封装 download→parse→cleanup；`sessionCleanupContext` 用 `context.WithoutCancel` 派生 30s 独立 deadline —— **关键**：run ctx 超时后 session 解析仍要跑完，否则每次超时刷一堆噪声日志。

### transcript 归一（→ `pkg/transcript.Transcript`）
- **Claude/QoderCLI**：共享 `parseSessionFile`（同 schema，历史 fork 红利）；token 取 max（usage 是累计快照不是增量）。
- **Codex**：两套解析器（stdout NDJSON + session JSONL），两阶段关联（`item.started` 记 call，`item.completed` 配对补 result）。
- **Qwen**：Gemini schema（`role:user/model`，`parts[]` 携带 text/functionCall/functionResponse）。
- **Custom**：信任引擎返回的 `transcript` 字段，没给就用 `minimalCustomTranscript` 拼；全量过 `maskTranscript` 脱敏。

## 子系统 ③ Runtime 隔离 + Report 生成

### Runtime 接口（13 方法，[runtime.go:118-153](../internal/runtime/runtime.go#L118)）
4 组：生命周期(Create/Close/Start/Stop) / 文件传输(Upload/Download × File/Dir) / 执行(Exec/MergeEnv) / 元信息(Workspace/RequiresProcessSandbox/Shell)。
- **工厂 + Shell 校验**：构造期就拒绝矛盾组合（如「Windows + posix 但没 BashPath」）。
- **`RequiresProcessSandbox()`**：none 返回 true（主机执行，危险，agent 要再套沙箱）；opensandbox/docker 返回 false（已有容器隔离）。
- **`Shell()` 返回目标 shell 而非主机 shell**（Windows 主机 + Linux 容器要用 POSIX 语法）。

### 三种后端

| 后端 | 实现 | 关键点 |
|------|------|--------|
| **none**（本地） | [none.go](../internal/runtime/none.go) | `MkdirTemp` 隔离；进程组 SIGTERM→SIGKILL 升级；`classifyExecError` 四态区分；UploadFile 保留权限位(对齐 opensandbox 契约) |
| **opensandbox**（远程） | [opensandbox.go](../internal/runtime/opensandbox.go) | 对接 Alibaba OpenSandbox HTTP API；批量上传(128/批控 fd) + 并发下载(8 worker, fail-fast)；networkPolicy→SDK NetworkPolicy；目录 API 失败优雅降级到 shell 验证 |
| **docker**（本地容器） | [docker.go](../internal/runtime/docker.go) | 不依赖 docker SDK，直接 shell out `docker`；`create→start→exec`；`--network none`(deny_all)；`sh -c` 兼容 alpine；env 字面透传(不展开 $PATH 避免污染)；snapshotContainerID 短锁防串行化 |

### platform.Shell 抽象（[platform.go](../internal/runtime/)）
`GOOS + Family(posix/cmd) + BashPath` 三元组描述目标 shell；`Quoter()` 按 family 返回正确引用函数（cmd→QuoteWindows，posix→QuotePOSIX）。上层一套命令拼接，引用规则自动适配。

### 配置系统（`internal/config/`）
- **eval.yaml schema**（v1alpha1）：9 顶层字段（environment/mcp/skills/engine/cases/judge/benchmark/report）。`Environment` 把 `NetworkPolicy`+`AllowedEgress` 做成一等字段。
- **Loader**：以 **SKILL.md 为锚点**解析相对路径（向上查最多 10 层）；case 未写 id 用文件名兜底；`SourceFile` 注入用于去重（`json:"-" yaml:"-"`）。
- **默认值分离**：只填 4 个「文档化默认」（timeout/max_turns/parallelism/report.formats），其他零值让 validator 拒绝（避免默认值掩盖配置错误）；默认值 `//go:embed defaults.yaml` 加载（文档与代码不漂移）。
- **分层校验**：文档级 / 类型枚举 / runtime 特化(docker 要 image) / 网络策略 / case 级 / 去重(路径归一化) / judge 合并。
- **延迟校验**：`engine.custom` 校验故意延到 `--engine` override 后（`ResolveCustomEngineConfig`）。
- **子集校验正确性**：`run` 只校验选中 case，`validate` 校验全量；去重基于 SourceFile 对任意子集正确。
- **MCP 合并**（[mcp_merge.go](../internal/config/mcp_merge.go)）：按 name **整条替换**（非字段级深合并），同名替换、新名追加保序；MVP 阶段 case-level 必须 mocked；返回 deep copy（不可变配置）。

### Report 生成（`internal/report/`）
- **策略模式**：`Reporter` 接口 + JSON(事实源)/JUnit(CI)/HTML(人) 三视图；空路径写 stdout（管道友好）。
- **JUnit**：fail/error/skip 三态映射，`<properties>` 携带 judge.skills 让 CI 可查询。
- **HTML**：`//go:embed` 模板+logo，输出自包含可离线；数据塞 `<script>` JSON，前端接管交互（后端只渲染外壳）。
- **Anthropic 兼容**：`grading.json`/`benchmark.json`/`eval_metadata.json` 对齐 Anthropic 工具链（生态借力）。
- **Benchmark**：`ComputeBenchmark` 算 mean+stddev（pass_rate/time/tokens 4 指标）+ delta（见 02 B8）。
- **IterationWorkspace**：`<skill>-workspace/iteration-N/<case>/{with_skill,without_skill}/{grading.json,outputs/}`；`validateCaseID` 防 `..`/`/` 穿越。
