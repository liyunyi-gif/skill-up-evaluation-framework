# 07 · 核心流程讲解（考试系统比喻）

> 这份是「**口语版**」核心流程，用「自动化考试系统」打比方，方便记忆和面试复述。
> 想看严谨的架构与时序，去 [01-架构与核心流程.md](./01-架构与核心流程.md)；本篇主打好懂、好记、好讲。

---

## 核心能力（一句话）

> **把一个 Agent Skill，在真实 Agent 引擎里自动跑测试用例 → 打分 → 出报告，且可复现、可隔离、可对比。**

= **Skill 的「自动化考试系统」**：你出题（用例），它组考（装 Skill 进 Agent、发题、收卷）、判卷（打分）、发榜（报告）。

---

## 流程（敲 `skill-up run` 之后，按真实执行顺序）

### 第 0 步｜读卷子（加载配置）
读 `eval.yaml` + 所有 `cases/*.yaml` → 校验合法性（必填/枚举/互斥）→ 应用 override（`--engine`/`--model`/`--parallelism`）→ **只校验选中的用例**，被过滤的不阻塞。
> Java 类比：Spring 启动读 `application.yml` + 校验 `@ConfigurationProperties`。

### 第 1 步｜选监考老师（凭据 + 建 Agent）
按优先级解析 API Key（`flag` > `env` > `credentials.yaml`）→ 按 engine 名字**工厂创建 Agent 适配器**（claude_code/codex/qodercli/…）。
> 这一步定下「用哪个 Agent 引擎当考生」。

### 第 2 步｜开考（并发跑所有用例）
每个 case 一个 goroutine，**信号量限并发**（`parallelism`，1–256）→ 带 retry（timeout/error）+ 指数退避 → case 级 timeout 是**整次尝试的总预算**。

### 第 3 步｜单个用例的考试过程（核心中的核心，7 小步）

每个 case 都走这条链 —— **面试最该讲清楚的部分**：

| 顺序 | 干啥 | 为什么重要 |
|---|---|---|
| ① **建隔离考场** | Runtime 沙箱（none/opensandbox/docker） | 用例互不污染，用完即删 |
| ② **布置考场** | 装 Agent CLI → 装 MCP → 装**你的 Skill** → 上传测试夹具 | 把被测对象真正装进引擎 |
| ③ **发题收卷** | `Agent.Run(prompt)` → Skill 真的执行 → 收 transcript/产物 | 被测 Skill 的产出 = 「答卷」 |
| ④ **抓附加卷面** | workspace diff、生成的文件 | 给裁判看「改了哪些文件」 |
| ⑤ **快速预判** | `expect` 预检查（关键字/文件/退出码） | 失败直接 FAIL **短路**，省掉昂贵打分 |
| ⑥ **正式判卷** | Judge 打分（3 选 1，见下） | 核心打分环节 |
| ⑦ **出小分** | 合并 expect+judge 断言 → PASS/FAIL + 通过率 | 这个 case 的最终成绩 |

**第 ⑥ 步的三种判卷方式**（成本递增，按需选）：
- `rule_based`：规则匹配（最便宜，确定性）
- `script`：跑评分脚本（退出码即结论）
- `agent_judge`：再起一个 **LLM 当裁判**（最贵，阈值制，要 ≥ `pass_threshold`）

### 第 4 步｜发成绩单（汇总 + 报告）
- 按 case 分组（`with_skill` / `without_skill`）
- 写 `result.json`（事实源）+ `benchmark.json`（含 **A/B 基线对比**）+ 可选 `html`/`junit`
- 落到 `iteration-N/` 目录，自动续号可追溯
- 退出码：`0` 全过 / `1` 有失败 → **CI 直接用退出码判断**

## 一条贯穿的数据流（记住这个骨架就行）

```
eval.yaml ──▶ Runner ──▶ Evaluator(并发) ──▶ 每个case:
                                            ①沙箱 ②装Skill ③Agent.Run ④收产物 ⑤expect ⑥Judge ⑦出分
                                                  └──▶ Report(result/benchmark/html) + 退出码
```

---

## 面试 30 秒版（背这段）

> 「skill-up 是 Agent Skill 的评测框架。核心流程：读声明式 YAML 配置 → 工厂创建 Agent 适配器 → **并发跑每个用例**（带重试/超时）→ 单个用例内部：**建隔离沙箱 → 把 Skill 装进 Agent → 跑 prompt 收输出 → expect 预检查短路 → 再用 rule/script/LLM 裁判打分** → 最后汇总成 result.json/benchmark.json 报告，退出码驱动 CI。设计上用统一的 `judge.Input` 数据边界把**执行层和评测层解耦**。」
