# 06 · 快速上手（怎么用 skill-up）

> 先会用，再谈设计。这份是**实操指南**，带你从 0 跑通一次评测。
> ⚠️ 你在 **Windows** 上，有几处 Windows 专属注意点（已用 🪟 标出）。

---

## 0. 它到底干什么（30 秒）

你有一个 **Agent Skill**（给 AI Agent 用的技能包，本质是一个含 `SKILL.md` 的目录）。你想知道它到底好不好用、改一行会不会改坏。skill-up 让你：

1. 写几个 **YAML 测试用例**（描述「给 Agent 发什么 prompt、期望它输出什么」）；
2. 跑 `skill-up run`，它会把 Skill 装进真实 Agent（Claude Code / Codex / Qoder CLI），替你发 prompt、收输出；
3. 用**规则/脚本/LLM 裁判**自动打分，产出报告（通过率、失败原因、产物）。

= **Agent Skill 版的 JUnit**。

---

## 1. 前置准备

### 你需要有一个 Skill
就是一个目录里有 `SKILL.md`：
```
my-skill/
  SKILL.md        ← 你的技能定义（Markdown + frontmatter）
```
没有的话，先随便建一个最小的 `SKILL.md` 练手。

### 🪟 Windows 用户：选一种运行方式

skill-up 在 Windows 上的支持分两档：

| 你想干的事 | Windows 原生 | WSL2 |
|---|---|---|
| 构建 / 单元测试 | ✅ | ✅ |
| `none` runtime（本机直接跑命令） | ✅（走 cmd.exe） | ✅ |
| `opensandbox` runtime（远程沙箱） | ✅（远端是 Linux） | ✅ |
| `.ps1` / `.cmd` 脚本评分 | ✅ | — |
| `.sh` 脚本评分 | ✅（需 Git Bash，你有 `D:\Git\bin\bash.exe`） | ✅ |
| **跑真实 Agent（Claude Code/Codex/Qoder）** | ⚠️ 受限（Agent 用 bash+node 引导，cmd.exe 跑不了） | ✅ 推荐 |

**结论**：
- 只想体验「写用例 + 规则/脚本评分」→ **Windows 原生**就行。
- 想完整跑通「装 Agent → Agent 真的执行 → 打分」→ 用 **WSL2**（一个 Linux 环境，避免路径/凭据折腾）。

## 2. 安装 skill-up

### 方式 A：脚本装二进制（macOS/Linux/WSL）
```bash
curl -fsSL https://raw.githubusercontent.com/alibaba/skill-up/main/install.sh | bash
skill-up --version
```

### 🪟 方式 B：Windows 本地从源码构建（你有 Go 1.25+ 的话）
```powershell
# 在仓库根目录
go build -o bin/skill-up.exe ./cmd/skill-up
./bin/skill-up.exe --version
```
> 如果没装 Go：去 https://go.dev/dl/ 装 1.25+。

### 验证
```bash
skill-up --version   # 能打印版本号就 OK
```

## 3. 最小可用流程（3 步跑通）

### Step 1 — 写配置 `evals/eval.yaml`

在你的 Skill 目录里建 `evals/eval.yaml`：

```yaml
schema_version: v1alpha1

environment:
  type: none                 # 不需要隔离容器，直接本机跑

engine:
  name: claude_code          # 用 Claude Code 当 Agent 引擎（需配 ANTHROPIC_API_KEY）

cases:
  files:
    - evals/cases/hello-world.yaml
```

> 💡 当 `evals/eval.yaml` 所在目录往上能找到 `SKILL.md` 时，skill-up 会**自动安装当前这个 Skill**，不用手动声明 skills 路径。
> 💡 没写的字段走默认：JSON 报告、超时 300s、max_turns 10、并发 1。

### Step 2 — 写一个用例 `evals/cases/hello-world.yaml`

```yaml
input:
  prompt: |
    Please generate a Hello World program

expect:
  must_contain:
    - "Hello"
    - "World"
  must_not_contain:
    - "error"
```
> 用例 `id` 默认 = 文件名（`hello-world`）。`expect` 是**零成本预检查**：输出里必须有 Hello/World、不能有 error。这种简单检查不用写 judge。

### Step 3 — 校验 + 运行

```bash
skill-up validate          # 先校验配置（不启动 Agent）
skill-up run               # 正式跑
```

成功输出长这样：
```
Running 1 case(s) with agent claude_code
[Evaluator] Case hello-world: PASS (pass_rate: 100.0%)
[INFO] Results written to ./<skill-name>-workspace/iteration-1
```
退出码 `0` = 全过；`1` = 有失败/错误（CI 里直接用退出码判断）。

## 4. 看懂输出

跑完会在 Skill 目录**旁边**生成 `<skill-name>-workspace/`：
```
<skill-name>-workspace/
└── iteration-1/                    ← 第 1 轮（--iteration N 会生成多轮）
    ├── result.json                 ← 完整原始数据（事实源）
    ├── benchmark.json              ← 汇总统计（含 with/without skill 对比）
    ├── report.html                 ← 人类可读（需 --format html）
    └── <case-id>/
        └── with_skill/
            ├── grading.json        ← 这个用例的打分结果
            └── outputs/            ← Agent 生成的文件
```

- **`grading.json`**：看 `summary.pass_rate` 和每条 `expectations` 的 `passed`/`evidence`（失败原因）。
- **`result.json`**：看 `case_results[].grading.status`（PASS/FAIL/**ERROR**——ERROR 表示执行本身挂了，区别于 FAIL 断言没过）。
- 想要网页版报告：`skill-up run --format html` 或事后 `skill-up report result.json --format html`。

## 5. 常用命令速查

| 命令 | 作用 |
|---|---|
| `skill-up validate` | 校验 eval.yaml + 所有用例（**全量**） |
| `skill-up run` | 跑评测（默认只校验**选中**的用例） |
| `skill-up list-cases` | 列出所有用例 |
| `skill-up report result.json --format html` | 从已有结果重生成报告 |
| `skill-up import ./evals/evals.json` | 把 Anthropic 格式转成本项目 YAML |
| `skill-up init` | 生成用户配置模板（OTel/runtime_kwargs） |
| `skill-up debug judge input.json` | 单独调试 judge 模块 |

### `run` 常用 flag
```bash
skill-up run --include-case-name "basic-*"      # 只跑匹配的用例（glob）
skill-up run --exclude-case-name "*-flaky"      # 排除
skill-up run --engine codex --model openai/gpt-4 # 临时换引擎/模型
skill-up run --parallelism 4                     # 并发（1–256）
skill-up run --format html --format junit        # 多种报告
skill-up run --iteration 3                       # 跑 3 轮（每轮一个目录）
skill-up run --iteration 0                       # 自动续号（接上一次）
skill-up run -v                                  # debug 日志；-vv = trace
skill-up run --dry-run                           # 只看会跑哪些用例，不真跑
```

## 6. 进阶：三种评分方式怎么配

在用例里加 `judge` 块（或写在 eval.yaml 里当全局默认）：

**① rule_based（规则，最便宜）** —— 纯关键字/工具调用/文件检查
```yaml
judge:
  type: rule_based
  success:
    - output_contains: { all: ["Hello", "World"] }
  failure:
    - output_contains: { any: ["error", "Error"] }   # 命中任一就 FAIL
```

**② script（脚本，跑你的判定逻辑）** —— 退出码即结论
```yaml
judge:
  type: script
  script_path: evals/fixtures/scripts/check.sh   # 🪟 用 .ps1 也行
  timeout_seconds: 30
```
脚本通过环境变量拿数据：`EVAL_TRANSCRIPT_PATH` / `EVAL_FINAL_MESSAGE` / `EVAL_EXIT_CODE`；退出码 0=PASS。

**③ agent_judge（LLM 裁判，最贵）** —— 语义评测
```yaml
judge:
  type: agent_judge
  model: qwen3.6-plus
  criteria:
    - "identified the null pointer dereference issue"
    - "provided a specific fix suggestion"
  pass_threshold: 0.7      # 通过率 ≥ 0.7 才 PASS
```

> 选择原则：能用 rule_based 就别用 script，能用 script 就别用 agent_judge（省钱、可复现）。

## 7. 推荐方式：用 skill-upper 走对话式闭环

不想手写 YAML？仓库自带一个 **skill-upper** Agent Skill，装进你的 AI Agent（Codex / Claude Code）后，**用自然语言对话**就能：创建用例 → 运行 → 看报告 → 诊断失败 → 修 Skill/用例 → 再跑，闭环迭代。

```bash
# Codex 全局安装
npx skills add https://github.com/alibaba/skill-up/tree/main/skills/skill-upper -g -a codex -y
# Claude Code 全局安装
npx skills add https://github.com/alibaba/skill-up/tree/main/skills/skill-upper -g -a claude-code -y
```

然后在 Agent 里打开你的 Skill 项目，直接说：
```
Use skill-upper to evaluate this Skill. Read SKILL.md, create realistic
eval cases, validate, run skill-up, and summarize the biggest failures.
```

## 8. 凭据怎么给

优先级（高→低）：`--api-key` 参数 > 环境变量 > `~/.skill-up/credentials.yaml`

```bash
# 环境变量（按引擎）
export ANTHROPIC_API_KEY=sk-...      # claude_code
export OPENAI_API_KEY=sk-...         # codex
export QODER_PERSONAL_ACCESS_TOKEN=... # qodercli

# 或运行时传
skill-up run --api-key sk-ant-...
```
> 🪟 Windows PowerShell 用 `$env:ANTHROPIC_API_KEY = "sk-..."`。

## 9. 常见坑

| 坑 | 解法 |
|---|---|
| `command not found: skill-up` | 把安装目录加进 PATH（`~/.local/bin` 或 `bin/`） |
| 🪟 `.sh` 脚本评分失败 | 设 `SKILL_UP_Bash=D:\Git\bin\bash.exe`，或改用 `.ps1` |
| 🪟 真实 Agent 跑不起来 | 用 WSL2 跑（见第 1 节） |
| opensandbox 报鉴权错 | 没设 `OPENSANDBOX_API_KEY` |
| 中文 expect 总失败 | 模型输出语言和断言语言要对齐（英文 prompt→英文断言） |
| 改了配置没生效 | `skill-up validate` 先校验，看报错 |
| 路径找不到 | cases/fixtures 路径是**相对 SKILL.md 目录**，不是相对当前工作目录 |

## 10. 你的练习路径建议

1. 先在本仓库的 [examples/code-stats/](../examples/code-stats/) 里跑一遍现成示例（它有完整的 eval.yaml + cases + 脚本 judge），感受全流程。
2. 给自己的一个小 Skill 写 2–3 个 rule_based 用例，跑通。
3. 试 `--format html` 看网页报告。
4. 再尝试 script judge 和（有预算的话）agent_judge。
5. 等用熟了，回头看 [01-架构与核心流程.md](./01-架构与核心流程.md) 理解它背后怎么设计的。
